# Lessons, 2026-10-21

Three lessons from one operator's agent records, October 2026. Each says what failed, the rule, and how to check it.

## A model change is a harness change

**What failed.** A pre-registered evaluation changed one variable, the reviewer model, and kept every
other setting identical, including `temperature: 0`. The new model rejects any temperature value
("`temperature` is deprecated for this model"). The paid batch stopped on its first request. It spent
nothing, but the run recorded no HTTP status or error text, so the cause had to be found by hand.

**The rule.** Treat a model swap as a change to the harness around it, not a string edit. Settings,
token budgets, refusal behavior and output shape are all model-specific. Before any paid or long run,
send one minimal request with the exact registered settings and refuse the run on any rejection.
Record the provider's status and error body on every stop. Self-HPO (arXiv 2610.22791) starts from the
same premise: a harness tuned for one checkpoint may not target the next one's failure modes.

**Check.** After a model change, what would the run's own files say if the first request failed? If
the answer is "partial, 1 request, 0 spend" with no reason, the run is not diagnosable.

## A host has many trust stores; test each one at the consuming end

**What failed.** When eight intermediate CA keys were reported compromised (eMudhra, October 2026),
browsers had already blocked them and the operating system's CA package was patched. On the same
machine, Python's `certifi` and Node's bundled store still trusted a test site signed by the bad
intermediates. A first check of Python returned "refused" for an unrelated network reason; a second
run showed it trusted the bad site.

**The rule.** Every runtime can carry its own root list: each browser, the OS, Python certifi, Node,
Go, Java, Electron apps, containers and devices. "We updated" is a claim about one of them. Test each
client against a known-bad endpoint and a known-good one, and read the failure reason, not just the
exit status. The incident page (emudhra.we-have-a-problem.com) lists such endpoints, for example
`dv-g3b-emudhra.we-have-a-problem.com`.

**Check.** A trust test passes only when the bad host fails with a certificate error AND a normal
HTTPS site still works from the same client. Either half alone proves nothing.

## AI reviewers across disciplines: ask for prior work first, and never ask whether it is a breakthrough

**What failed.** A preprint reported that five AI models all called one theory a "paradigm shift"
(SSRN 6277519). Per its methods section and annex, each model saw only the author's papers. Its prompt
asked "Does the theory truly constitute a paradigm shift?" A replication gave three current models
the same theory, by text-only API calls with no tools. It used three prompts: the original, a neutral
one, and the neutral one plus an independent evidence file. Under the original, all three rated it
"partly new". The neutral prompt named four disciplines as separate reviewers and asked for prior work
first. Under it, all three rated it "not new" and named a 1974 book that, they said, made the core
argument. The framing alone moved the verdict.

**The rule.**
1. Ask for prior work, by author and year, before any judgment of novelty.
2. Ask what is wrong with the claim, not whether it is a breakthrough.
3. Name each discipline as its own reviewer seat; breadth across fields is where models add most.
4. Give at least one reviewer an independently gathered evidence file, not the author's framing.
   Reviewers who read the same partial input share its blind spot, whatever their vendor.
5. Require citations and mark recalled ones as unverified, then check the load-bearing ones. In the
   replication, every model attributed the same claim to the 1974 book; the readily available source
   describes a narrower one.
6. Confirm every answer finished. One model's first answers were cut off at the token limit because
   its reasoning used half the budget; only the missing closing lines showed it.

**Check.** Run the same question under your prompt and under a deliberately neutral one. If the
verdict changes, the prompt was doing the reviewing.
